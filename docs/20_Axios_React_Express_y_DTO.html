1 Qué vas a aprender

Cuando una página React necesita datos que no tiene, como la lista de productos, tiene que pedírselos a un servidor por HTTP. Axios es la librería que hace esa solicitud por ti. Esta guía te enseña a usarla y después te muestra un proyecto real que la usa.

La guía tiene dos partes:

  • Axios desde cero. Qué es, cómo funciona, un ejemplo mínimo con código comentado para leer datos y para enviarlos, qué pasa cuando algo falla y en qué parte de un proyecto va cada pieza.
  • Trabajo autónomo con un proyecto ya hecho. Un proyecto completo con React y un backend (Express o Spring Boot) que ya usa Axios. Tú lo ejecutas, lo exploras y lo amplías siguiendo una lista de tareas.

Después de las tareas encuentras secciones de apoyo que explican el código del proyecto. Son opcionales: consúltalas solo cuando te atasques.

2 Qué es Axios y cómo funciona

Axios es una librería de JavaScript para hacer solicitudes HTTP. En una aplicación React corre en el navegador: le pide o le envía datos a un servidor y te devuelve su respuesta. Sin ella tendrías que armar a mano la solicitud, convertir el JSON y revisar los errores. Axios resuelve esas tres cosas.

Cómo funciona una llamada

  1. Llamas a una función de Axios con la dirección del servidor, por ejemplo axios.get(url).
  2. Axios arma la solicitud HTTP y la envía desde el navegador.
  3. Mientras el servidor responde, tu página no se congela. Axios te entrega una promesa, que es un valor que todavía no llegó.
  4. Cuando el servidor responde bien, la promesa se cumple y entrega un objeto con la respuesta. Si algo falla, la promesa se rechaza y entrega un error.
  5. Con await esperas ese resultado dentro de una función async, y con try/catch decides qué hacer en cada caso.

Qué pasa en una llamada

Este diagrama de secuencia sigue una llamada axios.get entre tu código, Axios y el servidor, primero cuando todo sale bien y luego cuando el servidor responde con error. Fíjate en que la promesa vuelve a tu código antes de que llegue la respuesta: mientras está pendiente, await espera. Si el estado es de 200 a 299, la promesa se cumple y sigues en el try. En cualquier otro caso se rechaza y saltas al catch.

Axios o fetch

El navegador ya trae fetch para hacer solicitudes. Funciona, pero Axios te ahorra trabajo repetido:

Qué necesitasfetchAxios
Leer el JSON de la respuestaUn paso aparte: await respuesta.json().Ya viene convertido en respuesta.data.
Enviar un objeto como JSONHay que usar JSON.stringify y escribir el encabezado a mano.Le pasas el objeto y Axios hace el resto.
Errores 400, 404 o 500No rechaza la promesa: tú tienes que revisar respuesta.ok.Rechaza la promesa y entra al catch.
Tiempo máximo de esperaSe programa aparte.Es una opción: timeout.
Dirección base compartidaNo existe.Una instancia con baseURL.

3 Ejemplo mínimo: leer datos con GET

Este es el ejemplo más pequeño posible. Pide la lista de productos a una API y muestra lo que recibe. Léelo línea por línea con los comentarios:

Ejemplo mínimo: GET
// 1. Importa Axios (se instala con: npm install axios)
import axios from 'axios'

// 2. async permite usar await dentro de la función
async function listarProductos() {
  try {
    // 3. axios.get envía un GET a esa dirección y devuelve una promesa.
    //    await espera a que el servidor responda antes de seguir.
    const respuesta = await axios.get('http://localhost:3000/api/productos')

    // 4. respuesta es un objeto. status trae el estado HTTP y data trae
    //    el cuerpo JSON ya convertido en un arreglo de JavaScript.
    console.log(respuesta.status) // 200
    console.log(respuesta.data) // [ { id: 1, nombre: 'Cuaderno', precio: 2500, stock: 8 } ]
  } catch (error) {
    // 5. Si algo falla (error HTTP, sin conexión, tiempo agotado) se salta aquí.
    console.log('No se pudo leer la lista')
  }
}

listarProductos()

Qué hace

  1. axios.get(url) envía un GET a la dirección. Un GET sirve para leer: no envía datos ni cambia nada en el servidor.
  2. await detiene esa función hasta que el servidor responde. El resto de la página sigue funcionando.
  3. La respuesta llega como un objeto. respuesta.status es el estado HTTP y respuesta.data es el cuerpo, ya convertido de JSON a un arreglo de JavaScript.
  4. Si cualquier cosa sale mal, el programa salta al catch y no se rompe.
Una función con await siempre se declara async. Sin esa palabra, JavaScript muestra un error de sintaxis.
4 Ejemplo mínimo: enviar datos con POST

Para crear algo en el servidor usas POST. La diferencia con el GET es que ahora envías un objeto en el cuerpo de la solicitud:

Ejemplo mínimo: POST
import axios from 'axios'

async function guardarProducto() {
  // El objeto que quieres enviar. No lleva id: lo genera el servidor.
  const producto = { nombre: 'Cuaderno', precio: 2500, stock: 8 }

  try {
    // El segundo argumento de post es el cuerpo de la solicitud.
    // Axios lo convierte a JSON y agrega el encabezado Content-Type.
    const respuesta = await axios.post('http://localhost:3000/api/productos', producto)

    // La API responde 201 (creado) y devuelve el producto con su id nuevo.
    console.log(respuesta.status) // 201
    console.log(respuesta.data) // { id: 1, nombre: 'Cuaderno', precio: 2500, stock: 8 }
  } catch (error) {
    console.log('No se pudo guardar el producto')
  }
}

guardarProducto()

El diagrama de secuencia muestra qué hace Axios con tu objeto: lo convierte a JSON para enviarlo y lo vuelve a convertir en objeto cuando el servidor responde. Si los datos no son válidos, la promesa se rechaza y el código salta al catch.

Qué hace

  1. Defines el objeto con los datos del producto. Todavía no tiene id: lo asigna el servidor.
  2. axios.post(url, objeto) recibe la dirección y, como segundo argumento, el cuerpo. Axios lo convierte a JSON y agrega solo el encabezado Content-Type: application/json.
  3. El servidor valida los datos, crea el producto y responde 201, que significa "creado".
  4. En respuesta.data viene el producto con su id nuevo. Es lo que mostrarías en pantalla. El id es un número en el backend Spring Boot y un texto largo en el de Express; en el ejemplo se muestra como 1 solo para simplificar.
ParaMétodo de AxiosArgumentos
Leeraxios.get(url)La dirección.
Crearaxios.post(url, datos)La dirección y el objeto a enviar.
Reemplazaraxios.put(url, datos)La dirección con el id y el objeto completo.
Eliminaraxios.delete(url)La dirección con el id. No lleva cuerpo.
5 Qué devuelve Axios y qué pasa cuando falla

El objeto de respuesta

Cuando la llamada funciona, await te entrega un objeto con varias propiedades. Las que más vas a usar son las dos primeras:

PropiedadQué contieneEjemplo
dataEl cuerpo de la respuesta, ya convertido de JSON.[ { id: 1, nombre: 'Cuaderno' } ]
statusEl código de estado HTTP.200 o 201
statusTextEl texto de ese estado.OK
headersLos encabezados que envió el servidor.content-type

Cuando falla: tres casos distintos

Axios rechaza la promesa si el estado queda fuera de 200 a 299 o si nunca llega una respuesta. Pero no todos los fallos significan lo mismo, y el catch tiene que distinguirlos:

Este diagrama de secuencia muestra los tres casos de error, uno debajo del otro. Cada uno corresponde a una rama del catch del ejemplo:

Ejemplo mínimo: errores
import axios from 'axios'

async function buscarProducto() {
  try {
    // Este id no existe, así que la API responde 404.
    await axios.get('http://localhost:3000/api/productos/999')
  } catch (error) {
    if (error.response) {
      // Caso 1: el servidor respondió, pero con un estado de error (400, 404, 500...).
      console.log(error.response.status) // 404
      console.log(error.response.data) // { mensaje: 'Producto no encontrado.', detalles: [] }
    } else if (error.code === 'ECONNABORTED') {
      // Caso 2: se agotó el tiempo de espera (opción timeout).
      console.log('La API tardó demasiado')
    } else {
      // Caso 3: no hubo respuesta (backend apagado, red caída o CORS).
      console.log('No fue posible contactar la API')
    }
  }
}

buscarProducto()
CasoCómo lo reconocesQué significa
El servidor respondió con errorExiste error.responseLa API funciona, pero rechazó la solicitud (datos inválidos, id inexistente). En error.response.data está el motivo.
Se agotó el tiempoerror.code vale ECONNABORTEDEl servidor tardó más que el timeout que configuraste.
No hubo respuestaNo existe error.responseEl backend está apagado, la red falló o el navegador bloqueó la respuesta por CORS.
6 Qué necesitas saber de la API: su contrato

Para consumir una API necesitas conocer su contrato: la dirección, las rutas, los métodos, los datos de entrada y las respuestas. Los repositorios ya lo traen. Aquí te toca ver cómo lo usa el código.

ParteEjemploPara qué sirve
Dirección basehttp://localhost:3000/apiIdentifica la API en este ejemplo local.
Recurso/productosLos datos que se consultan o se modifican.
MétodoGET o POSTLeer o crear.
Cuerpo de entradanombre, precio, stockLos datos que viajan en JSON al crear.
RespuestaEstado HTTP y cuerpo JSONLe comunica el resultado al frontend.

La dirección base y la ruta se suman: http://localhost:3000/api más /productos da http://localhost:3000/api/productos. Esa dirección tiene que ser accesible desde el navegador que ejecuta React, y localhost es el computador de ese navegador.

7 Dónde va Axios en un proyecto

Ya sabes llamar a una API con Axios. Ahora viene la pregunta de un proyecto real: ¿en qué archivo escribo cada cosa? Si pones las llamadas dentro de los componentes, terminas repitiendo direcciones y mezclando el dibujo de la pantalla con la comunicación. Por eso cada pieza tiene su lugar.

La estructura

Estructura de carpetas
src/
  services/     Axios: la instancia (api.js) y una función por cada operación
  dto/          Arma el cuerpo que exige la API a partir de los datos del formulario
  components/   Solo dibujan: reciben datos y funciones por props (atoms a templates)
  pages/        Llaman al service, guardan la respuesta en el estado y la reparten
PiezaQué haceQué no hace
ServiceUsa Axios. Tiene una función por cada operación de la API.No sabe nada de React ni del estado.
DTOPrepara los datos que se envían, con el formato exacto que pide la API.No llama a la API.
PáginaLlama al service, guarda la respuesta en el estado y maneja los errores.No dibuja detalles de la interfaz.
ComponenteDibuja lo que recibe por props y avisa con funciones que también recibe por props.No conoce a Axios ni a la dirección de la API.
Regla de oro. Axios solo vive en el service. Los componentes no saben que existe: reciben datos y funciones por props.

Cómo se comunican las capas

El diagrama sigue dos recorridos: pedir datos con GET y enviar datos con POST. Observa en qué momento aparece cada DTO:

El DTO: lo que envías y lo que recibes

Un DTO (Data Transfer Object) es el objeto con los campos que viajan entre tu aplicación y la API. Hay uno para cada sentido:

DTOSentidoQuién lo armaDónde lo ves
De entrada (request)De tu app hacia la APITu código, en dto/, a partir del formularioSegundo argumento de api.post(url, dto)
De salida (response)De la API hacia tu appEl backendrespuesta.data

El DTO de entrada existe porque un formulario entrega todo como texto y la API espera números. Esta función hace esa conversión y deja pasar solo los campos del contrato:

src/dto/producto.dto.js
// Los inputs HTML entregan texto. El contrato de la API exige números.
export function crearProductoRequestDto(formulario) {
  return {
    nombre: formulario.nombre.trim(),
    precio: Number(formulario.precio),
    stock: Number(formulario.stock)
  }
}

Cómo pedir datos, paso a paso

  1. Crea la instancia de Axios una sola vez, con la dirección base y el tiempo máximo de espera (src/services/api.js).
  2. Escribe una función por operación en el service. Cada una usa la instancia y devuelve respuesta.data.
  3. Si envías datos, arma el DTO de entrada a partir del formulario antes de llamar al service.
  4. Llama al service desde la página, dentro de un try/catch. Para leer, usa un useEffect; para guardar, una función que se ejecuta al enviar el formulario.
  5. Guarda el resultado en el estado con setProductos y entrégalo a los componentes por props.

Así se ven los pasos 2 y 4 en su versión mínima:

src/services/productoService.js
// src/services/productoService.js
import { api } from './api'

// GET: la API devuelve un arreglo de productos (el DTO de salida).
export async function listarProductos() {
  const respuesta = await api.get('/productos')
  return respuesta.data
}

// POST: recibe el DTO de entrada que armó el formulario y devuelve el producto creado.
export async function guardarProducto(dto) {
  const respuesta = await api.post('/productos', dto)
  return respuesta.data
}
src/pages/ProductosPage.jsx
// src/pages/ProductosPage.jsx (versión mínima)
const [productos, setProductos] = useState([])
const [errorLista, setErrorLista] = useState('')

// El efecto pide la lista cuando la página aparece en pantalla.
useEffect(() => {
  async function cargar() {
    try {
      const datos = await listarProductos()
      setProductos(datos) // lo que respondió la API pasa al estado
    } catch (error) {
      setErrorLista('No fue posible cargar la lista')
    }
  }
  cargar()
}, [])

// Más abajo, la página entrega el estado a un componente por props:
// <ListaProductos productos={productos} error={errorLista} />

10 Apoyo: cómo se conectan las piezas

Apoyo opcional. Consúltalo cuando lo necesites para resolver las tareas.

Desde aquí trabajas con el proyecto de ejemplo, que ya usa lo que acabas de ver. Axios corre en el navegador, envía la solicitud al backend y espera su respuesta. El diagrama muestra el camino completo de una solicitud.

  1. La persona abre la página o envía el formulario.
  2. React llama a una función del service.
  3. Axios envía un GET o un POST a la API.
  4. El backend valida, consulta o guarda, y responde con JSON.
  5. React guarda la respuesta en su estado y dibuja la lista de nuevo.

Una llamada HTTP tarda y puede fallar, así que Axios devuelve una promesa. await espera el resultado dentro de una función async, y try/catch deja mostrar un error si algo sale mal.

Son aplicaciones independientes. React no importa el código del backend ni toca sus datos. Solo envía solicitudes HTTP a sus rutas, y el backend (Express o Spring Boot) decide qué acepta y cómo lo guarda.
11 Apoyo: Axios en el proyecto, una instancia y un service

Apoyo opcional. Consúltalo cuando lo necesites para resolver las tareas.

La configuración de Axios vive en un solo módulo. Así los componentes no escriben direcciones ni repiten opciones.

src/services/api.js
import axios from 'axios'

// Una instancia comparte dirección base y tiempo máximo entre solicitudes.
export const api = axios.create({
  baseURL: import.meta.env.VITE_API_URL || 'http://localhost:3000/api',
  timeout: 10000
})

baseURL es la dirección común: api.get('/productos') la agrega por delante. timeout limita la espera a 10 segundos. Vite lee VITE_API_URL del archivo .env cuando inicia o construye el proyecto.

El service reúne las llamadas HTTP:

src/services/productoService.js
import { api } from './api'

export async function listarProductos(signal) {
  const respuesta = await api.get('/productos', { signal: signal })
  // data es el cuerpo JSON; status y headers pertenecen a la respuesta HTTP.
  return respuesta.data
}

export async function guardarProducto(dto) {
  const respuesta = await api.post('/productos', dto)
  return respuesta.data
}

respuesta.data es el cuerpo JSON y respuesta.status es el estado (200, 201...). En un POST, el segundo argumento es el objeto que Axios envía como JSON. signal permite cancelar la lectura con AbortController cuando la página se desmonta.

Actualizarapi.put('/productos/ID', dto)Existe en la API; pruébalo en Postman.
Eliminarapi.delete('/productos/ID')Existe en la API y responde 204 sin cuerpo. Es el ejercicio del final.
CORS. React (puerto 5173) y el backend (puerto 3000) son orígenes distintos. El backend deja leer sus respuestas solo al origen exacto que indica CORS_ORIGINS, tanto en Express como en Spring Boot. CORS regula lo que el navegador permite leer y no autentica a nadie.
12 Apoyo: guardar un producto, paso a paso

Apoyo opcional. Consúltalo cuando lo necesites para resolver las tareas.

El diagrama de secuencia sigue un clic en Guardar producto, desde el formulario hasta los datos y de vuelta, primero con datos válidos y después con datos inválidos:

Cada flecha corresponde a una pieza del código. Léelas en este orden con el proyecto abierto:

  1. Formulario. Al enviar, enviar en FormularioProducto.jsx cancela la recarga de la página y revisa que el nombre tenga al menos dos caracteres.
  2. DTO del frontend. crearProductoRequestDto convierte los textos del formulario en números y arma el dto. Luego el formulario llama a props.onGuardar(dto).
  3. Página. onGuardar es la función crearProducto de ProductosPage.jsx. Marca que está guardando y llama a guardarProducto(dto).
  4. Service y Axios. guardarProducto ejecuta api.post('/productos', dto). Axios agrega la dirección base y envía el JSON.
  5. Backend: DTO de entrada. La API valida el cuerpo y se queda solo con nombre, precio y stock. Si algo no cumple, responde 400 y el recorrido salta al caso de errores que verás más adelante.
  6. Backend: service y datos. El service crea el producto con un id nuevo y lo guarda (en un archivo JSON con Express, en la base H2 con Spring Boot).
  7. Respuesta. La API responde 201 con el DTO de salida: el producto con su id y sin fechaCreacion.
  8. De vuelta en React. Axios entrega el cuerpo en respuesta.data, y guardarProducto se lo devuelve a la página.
  9. Estado. crearProducto agrega el producto a la lista con setProductos y devuelve true. El formulario ve ese true, limpia sus campos y React dibuja la tarjeta nueva.

El DTO: los datos que viajan

DTO significa Data Transfer Object: un objeto con los campos que se transfieren entre dos partes del sistema. No es un componente ni una tabla de la base de datos. En el recorrido hay dos tipos.

En React, el DTO de entrada convierte los textos del formulario en el cuerpo que exige la API:

src/dto/producto.dto.js (frontend)
// Los inputs HTML entregan texto. El contrato de la API exige números.
export function crearProductoRequestDto(formulario) {
  return {
    nombre: formulario.nombre.trim(),
    precio: Number(formulario.precio),
    stock: Number(formulario.stock)
  }
}

En el backend, el DTO de entrada valida y deja pasar solo los campos permitidos, y el DTO de salida decide qué devuelve. Las reglas son las mismas en Express y en Spring Boot:

CampoRegla del DTO de entrada
nombreTexto de 2 a 80 caracteres, sin contar los espacios de los lados.
precioNúmero entre 0 y 100000000.
stockEntero entre 0 y 1000000.
idNo lo envía el cliente, lo genera el servidor. Si llega, se descarta.

El DTO de salida devuelve id, nombre, precio y stock. El campo fechaCreacion queda guardado pero no viaja. El backend valida otra vez aunque React ya lo haya hecho, porque cualquier cliente puede llamar a la API sin pasar por tu formulario.

Este es el mismo POST en cada backend. Primero Express:

Express: src/routes/producto.routes.js
  router.post('/', (req, res) => {
    const entrada = crearProductoEntradaDto(req.body);

Y ahora Spring Boot:

        return ResponseEntity.created(URI.create("/api/productos/" + creado.getId())).body(creado);

@RequestBody convierte el JSON en un ProductoEntradaDTO y @Valid ejecuta sus validaciones. Si fallan, el manejador de errores responde 400 con la misma forma { mensaje, detalles } que usa Express. Si pasan, el service crea el producto y el controlador responde 201.

Spring Boot: dto/ProductoEntradaDTO.java
// DTO de entrada: lo que el cliente envía en POST y PUT. Solo declara tres campos:
// si llega un id o cualquier otro dato, Jackson lo ignora. El id lo genera el servidor.
@Data
@NoArgsConstructor
public class ProductoEntradaDTO {

    @NotNull(message = "El nombre es obligatorio.")
    @Size(min = 2, max = 80, message = "El nombre debe tener entre 2 y 80 caracteres.")
    private String nombre;

    @NotNull(message = "El precio es obligatorio.")
    @DecimalMin(value = "0", message = "El precio debe ser un número entre 0 y 100000000.")
    @DecimalMax(value = "100000000", message = "El precio debe ser un número entre 0 y 100000000.")
    private BigDecimal precio;

    @NotNull(message = "El stock es obligatorio.")
    @Min(value = 0, message = "El stock debe ser un entero entre 0 y 1000000.")
    @Max(value = 1000000, message = "El stock debe ser un entero entre 0 y 1000000.")
    private Integer stock;

    // Los espacios a los lados no cuentan: se quitan antes de validar el largo.
    public void setNombre(String nombre) {
        this.nombre = nombre == null ? null : nombre.strip();
    }
}

La diferencia está en cómo se escriben las reglas. Express las revisa con una función sobre el cuerpo, y Spring Boot las declara con anotaciones sobre cada campo. En los dos casos, Axios recibe el DTO de salida en respuesta.data.

De la respuesta al estado

Cuando la página aparece, pide la lista y guarda el arreglo en su estado con setProductos(datos). React dibuja de nuevo, y la página entrega ese estado hacia abajo como props:

src/pages/ProductosPage.jsx

El acceso con punto, props.algo, lee los valores y las funciones que recibe un componente. algo es el nombre de la propiedad: props.productos, props.onGuardar. Así lo hace la lista:

src/components/organisms/ListaProductos/ListaProductos.jsx
import { Row, Col } from 'react-bootstrap'
import { TarjetaProducto } from '../../molecules/TarjetaProducto/TarjetaProducto'

// Organismo: la lista de productos. Según lo que reciba por props, dibuja
// el estado de carga, el error, la lista vacía o las tarjetas.
export function ListaProductos(props) {
  if (props.cargando) return <p role="status">Cargando productos...</p>
  if (props.error) return <p>La lista no está disponible. Usa el botón para reintentar.</p>
  if (props.productos.length === 0) return <p className="text-body-secondary">Todavía no hay productos. Guarda el primero.</p>

  return (
    // xs={12} md={6}: una tarjeta por fila en celular y dos desde tablet.
    <Row className="g-3">
      {props.productos.map((producto) => (
        // key identifica cada tarjeta con el id que asignó el backend.
        <Col xs={12} md={6} key={producto.id}>
          <TarjetaProducto producto={producto} />
        </Col>
      ))}
    </Row>
  )
}

map() convierte cada producto en un elemento y key lo identifica con el id que asignó el backend. La tarjeta lee props.producto.nombre, props.producto.precio y props.producto.stock.

En el formulario, props.onGuardar(dto) llama a la función que le entregó la página. La página hace el POST y agrega a su estado el producto que devolvió el servidor:

src/pages/ProductosPage.jsx: crearProducto
  async function crearProducto(dto) {
    setGuardando(true)
    setErrorGuardado('')
    setExito('')
    try {
      const creado = await guardarProducto(dto)
      // Usamos el DTO de respuesta: su id lo asignó el backend.
      setProductos((anteriores) => anteriores.concat(creado))
      setExito('Producto guardado correctamente.')
      return true
    } catch (error) {
      setErrorGuardado(obtenerMensajeError(error))
      return false
    } finally {
      setGuardando(false)
    }
  }

El formulario limpia sus campos solo si props.onGuardar devuelve true. El bloque finally apaga el estado "guardando" tanto si hubo éxito como si hubo error.

const [nombre, setNombre] = useState('') desestructura el resultado de un hook. No desestructura las props.
14 Apoyo: cuando algo falla en el proyecto

Apoyo opcional. Consúltalo cuando lo necesites para resolver las tareas.

Axios rechaza la promesa si el estado HTTP queda fuera de 200 a 299, o si nunca llega una respuesta. El catch tiene que distinguir los casos para mostrar un mensaje útil. Son los tres casos que viste en la sección 5, aplicados al proyecto:

src/services/productoService.js: obtenerMensajeError
export function obtenerMensajeError(error) {
  if (error.response) {
    // Hubo respuesta HTTP: por ejemplo, 400 con errores del DTO de entrada.
    const datos = error.response.data
    if (datos && typeof datos.mensaje === 'string') {
      const detalles = Array.isArray(datos.detalles) ? datos.detalles.join(' ') : ''
      return datos.mensaje + (detalles ? ' ' + detalles : '')
    }
    return 'La API respondió con un error (' + error.response.status + ').'
  }
  if (error.code === 'ECONNABORTED') return 'La API tardó demasiado. Revisa su estado antes de volver a guardar.'
  // El navegador no permite distinguir aquí entre CORS, red y servidor detenido.
  return 'No fue posible contactar la API. Revisa la conexión, su dirección y CORS.'
}

El mensaje aparece dentro de la página, sin alert(). Si falla el guardado, el formulario conserva lo que escribiste. Un timeout no asegura que el servidor no haya guardado, así que actualiza la lista antes de volver a enviar para no duplicar el producto.
