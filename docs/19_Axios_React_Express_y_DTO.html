Conectar React con una API: Axios y DTO

Backend: Node.js y ExpressFrontend: React, Atomic Design y BootstrapModalidad: Demostración y práctica
0 Qué vas a construir

Vas a conectar una pantalla React con una API de productos. Al abrir la página, Axios consultará los productos. Al guardar un formulario, enviará sus datos al backend y mostrará el producto creado.

  • Backend: Node.js, Express y DTO. Tiene CRUD completo y guarda productos en un archivo JSON.
  • Frontend: React, Axios y Bootstrap. Permite guardar y listar, con Atomic Design y props.algo.

Los repositorios son independientes. Este ejemplo usa productos ficticios, sin login ni JWT, para concentrarse en la comunicación. El archivo JSON conserva los datos entre reinicios en una sola instancia; no reemplaza la base de datos del trabajo semestral.

1 Qué hace Axios

Axios es un cliente HTTP para JavaScript. En esta aplicación corre en el navegador: envía una solicitud a Express y recibe una respuesta. Express realiza la operación y devuelve JSON; React usa esos datos para actualizar la pantalla.

  1. La persona abre la página o envía el formulario.
  2. React llama a una función del service.
  3. Axios envía GET o POST a la API.
  4. Express valida, consulta o guarda y devuelve una respuesta HTTP.
  5. React actualiza su estado y vuelve a dibujar la lista.

Una llamada HTTP tarda y puede fallar. Axios devuelve una promesa; await espera su resultado dentro de una función async. try/catch permite mostrar un error si la solicitud falla.

3 Configurar Axios una sola vez

En un proyecto nuevo instalarías Axios con npm install axios. En este repositorio ya está declarado. Abre el archivo que crea su instancia:

src/services/api.js
import axios from 'axios';

// Una instancia comparte dirección base y tiempo máximo entre solicitudes.
export const api = axios.create({
  baseURL: import.meta.env.VITE_API_URL || 'http://localhost:3000/api',
  timeout: 10000
});

baseURL es la dirección común. Al llamar api.get('/productos'), Axios usará http://IP_PUBLICA_BACKEND:3000/api/productos. timeout limita la espera a 10 segundos. Vite obtiene VITE_API_URL desde el archivo de entorno al iniciar o construir el proyecto.

CORS: los puertos 5173 y 3000 son orígenes diferentes. Express permite el origen exacto configurado en CORS_ORIGINS. CORS controla lo que el navegador permite leer; no autentica usuarios ni reemplaza reglas de acceso.

4 Leer y guardar con un service

El service reúne las llamadas HTTP para que los componentes no repitan direcciones ni configuración:

src/services/productoService.js: GET y POST
import { api } from './api.js';

export async function listarProductos(signal) {
  const respuesta = await api.get('/productos', { signal: signal });
  // data es el cuerpo JSON; status y headers pertenecen a la respuesta HTTP.
  return respuesta.data;
}

export async function guardarProducto(dto) {
  const respuesta = await api.post('/productos', dto);
  return respuesta.data;
}

respuesta.data contiene el cuerpo JSON. respuesta.status es el estado HTTP, por ejemplo 200 o 201. En POST, el segundo argumento es el objeto que Axios enviará como JSON.

signal permite cancelar una lectura con AbortController. La página lo usa para no actualizar el estado con una solicitud que ya no necesita. No hace falta cancelar para comprender GET y POST, pero el ejemplo incluye la limpieza del efecto.

5 DTO: los datos que viajan

DTO significa Data Transfer Object: un objeto con los campos que se transfieren entre partes del sistema. No es un componente React ni una tabla de base de datos. En este ejemplo, el cliente envía nombre, precio y stock; el servidor devuelve esos campos más el id.

src/dto/producto.dto.js
// Los inputs HTML entregan texto. El contrato de la API exige números.
export function crearProductoRequestDto(formulario) {
  return {
    nombre: formulario.nombre.trim(),
    precio: Number(formulario.precio),
    stock: Number(formulario.stock)
  };
}

Los campos del formulario entregan texto. Number() convierte precio y stock a números. El formulario exige los tres campos; el backend vuelve a validarlos porque cualquier cliente puede enviar solicitudes sin pasar por React.

DTO de entrada: POST y PUT
{ "nombre": "Cuaderno", "precio": 2500, "stock": 8 }

El backend recibe JSON gracias a express.json(). Su DTO de entrada selecciona los campos admitidos y valida nombre, precio y stock. Los datos adicionales, como un id impuesto por el cliente, se descartan. El id se genera en el servidor.

src/dto/producto.dto.js
import { HttpError } from '../errors/HttpError.js';

// DTO de entrada: valida y selecciona los únicos campos que acepta la API.
// Se reutiliza en POST y PUT (PUT reemplaza los tres campos completos).
export function crearProductoEntradaDto(cuerpo) {
  if (!cuerpo || typeof cuerpo !== 'object' || Array.isArray(cuerpo)) {
    throw new HttpError(400, 'Debes enviar un objeto JSON.');
  }
  const errores = [];
  const nombre = typeof cuerpo.nombre === 'string' ? cuerpo.nombre.trim() : '';
  if (nombre.length < 2 || nombre.length > 80) {
    errores.push('El nombre debe tener entre 2 y 80 caracteres.');
  }
  if (typeof cuerpo.precio !== 'number' || !Number.isFinite(cuerpo.precio)
      || cuerpo.precio < 0 || cuerpo.precio > 100000000) {
    errores.push('El precio debe ser un número entre 0 y 100000000.');
  }
  if (!Number.isInteger(cuerpo.stock) || cuerpo.stock < 0 || cuerpo.stock > 1000000) {
    errores.push('El stock debe ser un entero entre 0 y 1000000.');
  }
  if (errores.length) throw new HttpError(400, 'Producto inválido.', errores);

  // No copiamos todo el cuerpo: id y fechaCreacion los controla el servidor.
  return { nombre: nombre, precio: cuerpo.precio, stock: cuerpo.stock };
}

// DTO de salida: fechaCreacion queda en el almacenamiento, no en el contrato.
export function crearProductoSalidaDto(producto) {
  return {
    id: producto.id,
    nombre: producto.nombre,
    precio: producto.precio,
    stock: producto.stock
  };
}

El archivo de almacenamiento contiene además fechaCreacion. El DTO de salida no la devuelve: muestra que el contrato puede ser distinto de la representación interna. Usar un DTO no valida automáticamente; las comprobaciones de la función realizan esa tarea.

Los componentes acceden a las propiedades mediante props.algo. Por ejemplo, la lista entrega un producto a la tarjeta:

src/components/organisms/ListaProductos.jsx
import TarjetaProducto from '../molecules/TarjetaProducto.jsx';

export default function ListaProductos(props) {
  if (props.cargando) return <p role="status">Cargando productos...</p>;
  if (props.error) return <p>La lista no está disponible. Usa el botón para reintentar.</p>;
  if (props.productos.length === 0) return <p className="text-body-secondary">Todavía no hay productos. Guarda el primero.</p>;
  return (
    <div className="row g-3">
      {props.productos.map(function (producto) {
        return <div className="col-12 col-md-6" key={producto.id}><TarjetaProducto producto={producto} /></div>;
      })}
    </div>
  );
}

La tarjeta lee props.producto.nombre, props.producto.precio y props.producto.stock. map() transforma los productos en elementos React y key identifica cada uno por su id. Las clases de Bootstrap organizan las tarjetas en columnas.

En el formulario, props.alGuardar(dto) llama a la función que recibió desde la página. La página ejecuta el POST y actualiza el estado con el producto devuelto:

src/pages/ProductosPage.jsx: crearProducto
async function crearProducto(dto) {
    setGuardando(true);
    setErrorGuardado('');
    setExito('');
    try {
      const creado = await guardarProducto(dto);
      // Usamos el DTO de respuesta: su id lo asignó el backend.
      setProductos(function (anteriores) { return anteriores.concat(creado); });
      setExito('Producto guardado correctamente.');
      return true;
    } catch (error) {
      setErrorGuardado(obtenerMensajeError(error));
      return false;
    } finally {
      setGuardando(false);
    }
  }

setProductos agrega el resultado del backend sin recargar toda la página. finally termina el estado de guardado tanto si hay éxito como si hay error. El formulario limpia sus campos solo cuando props.alGuardar devuelve true.

El uso de const [nombre, setNombre] = useState('') desestructura el resultado de un hook; no desestructura las props. Las llamadas HTTP y los DTO quedan fuera de los átomos, en services/ y dto/.

7 Errores: HTTP, red y CORS

Axios, con su configuración predeterminada, rechaza la promesa ante estados HTTP fuera de 200 a 299. No todos los errores son iguales:

src/services/productoService.js: errores
export function obtenerMensajeError(error) {
  if (error.response) {
    // Hubo respuesta HTTP: por ejemplo, 400 con errores del DTO de entrada.
    const datos = error.response.data;
    if (datos && typeof datos.mensaje === 'string') {
      const detalles = Array.isArray(datos.detalles) ? datos.detalles.join(' ') : '';
      return datos.mensaje + (detalles ? ' ' + detalles : '');
    }
    return 'La API respondió con un error (' + error.response.status + ').';
  }
  if (error.code === 'ECONNABORTED') return 'La API tardó demasiado. Revisa su estado antes de volver a guardar.';
  // El navegador no permite distinguir aquí entre CORS, red y servidor detenido.
  return 'No fue posible contactar la API. Revisa la conexión, su dirección y CORS.';
}

La pantalla muestra mensajes dentro de la página, sin alert(). Si falla el guardado, conserva los campos. Un timeout no asegura que el servidor no haya guardado: actualiza la lista antes de volver a enviar para evitar duplicados.

8 Recorrido de prueba para la clase
  1. Abre la pantalla y las herramientas del navegador. En Network filtra por Fetch/XHR y busca productos.
  2. Guarda un Cuaderno con precio 2500 y stock 8. Revisa el POST: URL, cuerpo enviado y respuesta 201 con id.
  3. Presiona Actualizar lista. Revisa el GET, estado 200 y arreglo de productos.
  4. Recarga el navegador: el producto vuelve a consultarse desde el backend, no desde localStorage.
  5. Importa la colección Postman incluida en el backend. Ajusta baseUrl, crea un producto y prueba GET por id, PUT y DELETE. La colección guarda automáticamente el id creado.
  6. Envía desde Postman un precio negativo y observa 400. Comprueba que no aparece en la lista.
  7. Detén la API y actualiza la lista. Lee el error; vuelve a iniciar la API y presiona Reintentar carga.

Si React StrictMode inicia y cancela una primera lectura en desarrollo, observa el GET que se completa. No implica que se haya enviado dos veces el formulario.
